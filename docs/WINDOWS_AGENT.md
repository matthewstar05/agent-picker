# Instructions for the Windows agent

Replicate the user's Mac `agent` command using this repository. Keep macOS and Windows on the same main branch.

1. Read `AGENTS.md` and `README.md`. Use a native Windows Terminal PowerShell tab. Check Python 3.9+, Git, and authenticated access to `https://github.com/matthewstar05/agent-picker`. If needed, the user must sign in to GitHub and the providers on this machine; do not import the Mac's credentials.
2. Clone the repo into a permanent path such as `$HOME\Projects\agent-picker`. If it already exists, inspect `git status` and pull with `git pull --ff-only` only when clean.
3. Inventory provider CLIs already installed: Claude (`claude`), Codex (`codex`), Cursor (`cursor-agent`, `cursor-cli`, or the vendor's `agent`), Kiro (`kiro-cli`), and Antigravity (`agy`). Inspect the installed CLI's help before changing a launch profile. Do not substitute models simply because a default model is unfamiliar. Missing provider installations or unsupported flags must be reported precisely.
4. Run `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1` from the repo. The installer captures Cursor's vendor path when necessary and adds the picker functions to user PowerShell profiles. It preserves existing local Cursor overrides. Use machine-local config for executable paths, not `agents.json`.
5. Open a fresh terminal and run `agent --picker-doctor`. Confirm that the `agent` command is a picker function with `Get-Command agent`. Confirm Cursor's executable points to its vendor launcher and does not recurse into the picker. If a profile cannot load, inspect execution policy and explain the cause; do not change administrator-managed policy.
6. Run `python -m unittest discover -s tests -v`. Verify the picker interactively: Up/Down and j/k, 1-5, saved selection, resize, Enter launch, q/Escape quit, and restoration of cursor, screen, and console input. Use a fake provider first when checking prompt forwarding and exit status. Run real signed-in providers only within the user's authorization.
7. Preserve the original models, efforts, bypass flags, animations, and folder trust behavior. If a CLI differs on Windows, prefer a local path or platform-specific profile override. Shared behavior fixes belong in this repo, with tests that cover both platforms.
8. Usage meters must be accurate or clearly unavailable. Windows Claude reads its own local credentials file, Codex reads its own session logs, and Kiro can use its own `/usage` command. Cursor and Antigravity have no verified Windows credential reader yet. Do not fabricate quotas or copy credentials to implement them. If adding a native reader, verify its storage format against the installed CLI and keep secrets out of output and Git.
9. For authorized shared improvements: pull, edit, test, commit, and push to this repo. Check macOS and Windows Actions results. On each computer run `agent --picker-update`. Rerun installers only when shell integration or installation changes. Never discard, reset, or auto-stash local modifications to force an update.

Completion means the picker works in a fresh Windows terminal and at least the user's installed providers can launch with their intended arguments. Passing CI alone does not confirm live authentication, quota readings, model availability, or terminal appearance. Report any remaining provider-specific gaps.
